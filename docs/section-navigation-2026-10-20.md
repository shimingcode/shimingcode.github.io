# 2026-10-20 主页分区导航改造

本轮在现有原生 HTML、CSS、JavaScript 项目中修改，没有引入框架、滚动插件或运行时依赖。继续沿用原有 esbuild 可选静态打包、内容哈希和 GitHub Pages 路径。没有提交、推送或部署。此前性能工作见 [10 月 18 日报告](fullsite-performance-2026-10-18.md) 与 [10 月 19 日报告](efficiency-review-2026-10-19.md)；此前的测量值不作为本轮结果。

## 导航与内容

主页现有八个独立分区：`#home`、`#links`、`#projects`、`#works`、`#games`、`#fox-game`、`#about`、`#music`。顶部沿用原有导航并增加音乐入口；狐娘互动归入“小游戏”高亮，也可以通过 `#fox-game` 直达。兼容旧 `#platforms` 和 `#funny-hit` 锚点。

- 普通站内点击使用原生平滑滚动及 `history.pushState`，不刷新文档；重复点击同一目标不增加历史记录。返回、前进、直接访问和刷新锚点均能恢复位置。修饰键、新标签、外链及显式独立页面入口保持浏览器默认行为。
- IntersectionObserver 更新当前分区高亮、触发一次性进入动画和邻近内容加载。ResizeObserver 测量实际固定栏高度，配合 `scroll-margin-top` 防止遮挡标题；减少动态效果设置下直接定位。没有持续滚动布局计算。
- 连续点击以最后一次为准；首次目标内容加载完成后才定位。延迟到达的上方内容会保留目标位置。平滑滚动的结束判断校验实际落点，兼容不支持 `scrollend` 的浏览器时有超时兜底。用户触控、鼠标或滚动键操作会中止尚未结束的自动滚动。
- 平台和项目复用首页现有完整功能；相册、翻牌和狐娘互动复用原独立 HTML 的主内容，首次需要时才加载专属脚本和样式。构建模式使用动态 import，源码模式使用按需脚本。已成功加载的功能不再次初始化。
- 游戏与相册 DOM 留在主页，翻牌牌面、难度、计数、狐娘点击进度和相册筛选保留。主动导航离开游戏或游戏区域完全离开视口时暂停非必要工作；翻牌返回后通过现有“继续游戏”按钮恢复。导航高亮处于相邻分区时，不再误暂停仍可操作的游戏。
- 原音乐元素、播放器、循环、音量、进度和光碟动画继续复用。音乐分区按钮打开同一个面板；首页播放器收起入口和助手放在页尾，展开的播放器仍为浮层，避免长页面游戏卡片被悬浮入口遮挡。浏览器自动播放限制仍由原有点击播放入口处理。
- 加载失败显示就地重试和独立页面入口。失败的 HTML、脚本和 CSS 不作为成功缓存；原生模块加载失败的重试使用新的尝试 URL，避免浏览器缓存失败结果。

## 保留的独立页面

`/links/`、`/projects/`、`/works.html`、`/games/`、`/games/funny-hit/`、`/about/` 全部保留，可直接打开和刷新，保持各自规范链接。它们同时是旧外链兼容入口、懒加载内容来源和异常时的独立页面回退。没有强制重定向或删除内容。

从旧页面点击站内导航时，会进入主页分区。已经存在的功能 DOM 被移入主页，相应监听器和状态复用；播放器始终留在同一个文档。整合前重新解析相对链接、图片和 srcset，图库动态资源统一从站点基础路径解析。根路径与 `/preview/` 子目录部署均有本地测试覆盖。

## 验证与性能记录

构建成功，生成 101 个发布文件；34 项静态、构建及游戏规则检查通过。17 组回归的最新结果全部通过，包含构建和源码模式。完整串行运行中，`efficiency`、`sections`、`compat` 三组出现进程超时，分别重新运行后通过；汇总是各套件最新结果，并非声称第一次整轮运行全部通过。没有把超时记录当成性能指标或断言其根因。

Edge 155.0.4283.62 与 WebKit 26.5 均通过 15 项分区专项检查；源码模式也通过 15 项。覆盖首屏零游戏/图库模块及音频请求、功能包单次加载、相册筛选与两个游戏状态保留、同一个音乐元素连续播放、历史记录不重复、直接锚点及刷新、正常/减少动画模式、快速导航、HTML/原生模块 503 后重试、旧页面入口、相对路径和子目录部署。正常导航中没有观测到新增控制台异常或资源 404；故障测试中的 503 为主动注入。

翻牌四种难度均完成，狐娘 100 次点击、100 条台词、10 阶段、通关与重置检查通过。Edge/WebKit 音乐测试覆盖实际进度、媒体状态及自动播放受阻后的手动恢复。重复导航并执行 GC 后，三轮观测均为 1,440 个 DOM 节点、124 个事件监听器，没有增长。

测试期间修复了两项实际问题：长距离滚动过早结束导致邻近模块加载后落点偏移；边界分区高亮误暂停仍可操作的游戏，以及用户开始操作后原生平滑滚动继续移动页面。修改后重新运行相关回归，未降低原有游戏断言要求。

已检查 320、390、768、844、1280 等视口下的布局，并人工查看生成的首页手机/桌面截图，保留粉色背景、毛玻璃、人物、头像与现有视觉层次。原始日志和截图位于 `test-results/fullsite-verification/`、`test-results/sections/` 和 `test-results/performance/`；可复现命令：

```powershell
npm run build
npm run test:regression
$env:BROWSER_ENGINE = 'webkit'
node tests/sections.cjs
```

首屏前后测量数据见同名 JSON，Lighthouse 原始报告为 `test-results/performance/lighthouse-sections-{before,after}.json` 和 `.html`。

## 部署与验证边界

- 没有远程部署，因此线上 GitHub Pages 发布结果、真实 CDN 缓存、线上网络 TTFB 尚未验证。本地已覆盖原路径、旧 HTML 地址与项目子路径；公开地址和 Pages 配置未变。
- 构建压缩与内容哈希只在 `_site/` 生效。仓库根目录源码也经过独立测试，但直接发布源码不会自动获得 bundle 压缩收益。没有新增 Service Worker 或缓存旧 HTML。
- 移动测试为桌面 Edge/WebKit 引擎的视口和触控模拟，不能代替 iPhone、iPad、Android 真机，也不能保证所有旧浏览器、低性能设备和后台音频策略。
- 没有真实用户 INP 数据；Lighthouse 的 TBT 不能替代 INP。自动化验证媒体状态、实际播放进度和资源复用，没有替代人工听音评价。
- 单页保留已经打开的模块会保留相应 DOM 与内存，这是保持游戏进度和筛选状态的必要代价；首次首页不加载这些模块。测试检查重复导航后的监听器和节点是否有持续增长，不代表数小时运行或全部设备的稳定性证明。
- 建议上线后核查真实移动网络的首屏、声音与后台恢复，并采集实际访问的 Core Web Vitals；本轮不自动发布。
