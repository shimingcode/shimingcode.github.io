# 2026-10-20 单页面改造后的首屏减负

本轮基于已完成的[单页面导航版本](section-navigation-2026-10-20.md)，针对新增首屏字节继续优化。未提交、推送或部署，没有修改游戏规则、台词、音乐状态逻辑或视觉样式。

## 原因与修改

上轮单次测量的新增传输约 46 KB，其中约 30 KB 来自“关于”分区的高清头像。原生 `loading="lazy"` 允许浏览器提前数屏取图；在高像素密度手机上，100px 的头像会选中 336px WebP，即使用户尚未浏览“关于”也会下载。

现在用一个复用的 IntersectionObserver，在头像接近视口 160px 时才赋予完整响应式源。此前保留已经被首页使用的 160px 小头像。头像尺寸、高清资源、响应式选择和直接访问 `#about` 的行为保留；成功升级后停止观察，再次导航不重新取图。配置更新与旧页面整合仍走同一初始化入口。

WebKit 专项检查还发现音乐封面设置 `srcset` 时，尚未设置 `sizes`，浏览器会按默认 100vw 短暂请求高清候选图。现在先设置显示尺寸，再设置候选源与回退地址；修改后 DPR 2 的 WebKit 首页不再触发这笔高清图请求。只调整图片属性顺序，没有改动音频播放、进度、音量或自动播放策略。

另外，将只有导入相册/游戏或从旧独立页面进入主页时才使用的 DOM 整合、相对路径处理、页面元信息迁移移到 `js/page-content.js`。首页分区定位、高亮和历史记录仍在常驻导航模块中，无需等待额外请求。共享内容模块首次需要时加载，构建模式采用带内容哈希的动态 import；源码模式使用既有脚本加载器。成功加载后复用，失败重试沿用原有处理。

| 修改文件 | 作用 |
| --- | --- |
| `js/main.js` | 延后非首屏头像高清源，设置正确尺寸后再选择响应式资源，复用一个图片观察器 |
| `js/router.js` | 保留即时分区导航，将内容整合操作交给按需模块；并行请求模块、HTML 和功能资源 |
| `js/page-content.js` | 从原导航文件提取原有内容整合逻辑，保持旧页面游戏 DOM、状态及路径处理 |
| `js/music.js` | 封面先设置 `sizes` 再设置图片源，避免 WebKit 瞬时下载不需要的高清图 |
| `scripts/build.mjs` | 为新按需模块生成压缩文件与内容哈希，加入既有资源清单，不加入首屏脚本 |
| 7 个 HTML：主页、平台、项目、相册、翻牌、狐娘、关于 | 同步 `main.js`、`router.js` 和 `music.js` 源码版本，保留公开路径 |
| `tests/sections.cjs` | 增加首屏不取共享内容模块、高密度手机高清头像延后加载、直接锚点、模块失败重试与重复访问复用检查 |
| `README.md`、本报告和同名 JSON | 记录实现、原始测量摘要与验证边界 |

首屏外部 JavaScript 内容从 **44,917 B 降至 43,555 B**，减少 **1,362 B**。提取的共享模块为 **1,859 B**，仅在需要时请求；它与额外观察器意味着全站代码总量略增，减少的是首屏成本，没有把“延后加载”说成删除功能。页面资源清单因此增加少量字节。CSS、游戏、音乐和图片素材没有改动；与本轮开始的构建快照逐字节比较，发布的 49 个素材文件、9,139,416 字节全部一致。

## 验证和测量

构建成功，生成 103 个发布文件。完整串行运行的 17 组回归全部通过，包含 34 项静态/构建/游戏规则检查，以及构建和源码模式。最后调整音乐封面属性顺序后，再次运行相关构建、分区、音乐和兼容性套件。Edge 155.0.4283.62、WebKit 26.5 的 17 项分区专项检查及源码模式 17 项检查均通过；原始日志与各套件最新结果位于 `test-results/fullsite-verification/` 和 `test-results/sections/`。

覆盖音乐实际播放和进度、翻牌四种难度、狐娘 100 次/10 阶段通关与原声复用、游戏状态保留、快速连续导航、正常/减少动画模式、前进后退、直接锚点、失败恢复、旧页面和子目录部署。三轮重复导航并 GC 后，观测均为 1,440 个节点和 124 个事件监听器，没有持续增长。正常测试未观测到新增脚本异常或资源 404；503 用于主动注入失败。

新检查还验证：DPR 2 手机冷启动不下载 336px 头像；进入关于后选中并成功解码高清资源；返回再进入不重复请求；`/preview/#about` 直接访问路径正确；共享内容模块首次 503 后原地重试成功，后续不同功能共用一次成功加载。

前版本为 `test-results/startup-baseline-2026-10-20/`，不是更早的多页面版本；后版本为本轮最终 `_site/`。此前报告中的单次测量不与本轮新测量混作同组数据。

Lighthouse 13.0.1、同一台 Windows 与 Edge 155.0.4283.62，默认移动模拟节流（CPU 4 倍减速），本地 no-store HTTP、无传输压缩。按前/后交替顺序各测三次，没有并行运行浏览器回归。下表为各指标独立计算的中位数；请求数和资源字节在各自三次测量中一致。

首屏传输稳定减少 **31,942 B（17.8%）**。LCP 前三次范围为 1,889.9–1,892.0 ms，后三次为 1,888.4–1,890.6 ms；差异很小，不能据此声称加载时间稳定提速。评分和 CLS 持平，TBT 中位数略增 1 ms。本轮明确收益为减少下载量和首屏代码；音乐、游戏与导航功能保持通过。

传输统计包含 HTTP 响应头，以及 Lighthouse 加载窗口中浏览器提前请求的图片，不等同于可见区域资源，也不包含稍后按需加载的全部游戏和媒体。本地服务响应时间不能代表线上 TTFB，TBT 不能替代真实用户 INP。

## 保留的边界

- 没有远程部署；线上 GitHub Pages/CDN、真实网络 TTFB、iPhone/iPad/Android 真机和真实用户 INP 未验证。
- 压缩及内容哈希收益来自 `_site/`。源码直出也单独测试，但不会自动采用构建 bundle。
- 低于首屏的模块首次进入时仍需要下载；失败有原地重试和原独立页面入口。已加载的模块保留，用于维持游戏和相册状态。
- 本轮没有新增 Service Worker、运行时依赖或压缩图片，保留原画质及旧资源。音乐和游戏的按需音频策略不变。
